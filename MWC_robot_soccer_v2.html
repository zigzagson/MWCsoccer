MWC Soccer · Unitree G1 + Jetson NX · ROS2 三方协作规范

机器人点球与守门大战架构规划

目标是明确视觉 SDK、导航模块、ROS2 主控制节点之间的最小协作接口： 视觉 SDK 只向导航提供检测能力，导航统一广播球和球门的语义坐标，主控负责流程编排、动作触发和异常仲裁。

一、模块职责边界

视觉 SDK 导航内部调用的检测库

  • 作为 SDK 被导航模块调用，不单独设计 ROS2 发布节点。
  • 输入相机图像，输出球、球门框、机器人脚等像素级检测结果。
  • 返回检测结果；具体字段、数据结构和置信度规则由视觉与导航双方约定。
  • 不负责坐标转换、轨迹预测、机器人移动和动作触发。

导航模块 定点导航与视觉跟踪

  • 内部调用视觉 SDK，结合相机标定、TF、机器人姿态完成坐标转换。
  • 点球点位置固定；收到 PENALTY_ATTACK 后，根据目标进球点和球前距离计算定点导航点，并立即开始导航。
  • 通过 /soccer/nav_status 广播 navigating_to_point 与 target_reached，让主控判断定点导航是否完成。
  • 到点后接收视觉跟踪命令，开始/停止图像检测与球、球门坐标换算，并通过 /soccer/perception 输出球和球门在 dummy/本体坐标系下的位置。
  • 不计算点球 ALIGN 微调、不触发踢球动作；最终对位和全身动作由主控负责。

ROS2 主控制节点 流程编排与动作执行

  • 串联点球流程：发布带参数的 PENALTY_ATTACK、等待定点导航到达、打开视觉跟踪、ALIGN、关闭视觉跟踪、射门。
  • 串联守门流程：观察球、计算球轨迹、移动到拦截点、执行挡球动作。
  • 定点导航期间不接管导航速度；收到 target_reached 后再请求视觉跟踪并执行微调。
  • 通过 deploy_cpp 的 ROS2 action 接口触发射门等全身运控动作。
  • 负责安全仲裁、超时处理、状态机切换和日志记录。

三、ROS2 Topic 与信令表

正常广播

导航周期性调用视觉 SDK，并以固定频率发布 /soccer/perception。主控只根据该 topic 判断是否看见球、球在哪里、是否看见球门、球门在哪里。

丢球或丢门

如果 SDK 当前帧没有检测到目标，导航仍发布消息，但将 image_has_ball 或 image_has_goal 置为 false，坐标保留上一帧时必须在 detail 中标注 stale。

模式切换

主控向导航发 /soccer/game_mode_cmd 和 /soccer/vision_track_cmd。视觉 SDK 不接收主控命令，由导航决定调用哪些检测能力和输出频率。

动作仲裁

导航负责 PENALTY_ATTACK 后的定点导航；主控负责到点后的视觉跟踪开关、ALIGN 微调、射门动作和异常仲裁。任何动作触发前都必须检查 /soccer/nav_status 和最新 /soccer/perception。

Topic 发布方 → 订阅方 建议消息类型 QoS 用途
/soccer/perception 导航 → 主控 soccer_msgs/msg/SoccerPerception Reliable，Depth 10 视觉跟踪开启后广播：图像视野是否有球、球在 dummy/本体坐标系下的坐标、是否有球门、球门中心和门柱坐标。

1. SoccerPerception.msg

std_msgs/Header header
bool image_has_ball
bool image_has_goal
geometry_msgs/PointStamped ball # recommended frame_id: dummy
geometry_msgs/PointStamped goal_center
geometry_msgs/PointStamped left_post
geometry_msgs/PointStamped right_post
float32 ball_confidence
float32 goal_confidence
bool transform_valid
string detail
字段 含义 坐标约定 主控用途
ball 足球中心点的 3D 坐标。只有 image_has_ball=true 且 transform_valid=true 时可信。 默认 dummy。x 表示机器人前方距离，y 表示左右偏移，z 表示高度或投影高度。 点球到达定点导航点后用于最终对位；守门时用连续多帧 ball 计算球速、轨迹和拦截点。
goal_center 球门中心点坐标，通常由左右门柱或球门框检测结果计算得到。 与 ball 使用同一 frame_id，默认 dummy。 点球时用于确定射门方向；守门时用于定义球门线或防守中心。
left_post 从机器人当前视角定义的左侧门柱坐标。 与 goal_center 同坐标系。左右以机器人看向球门时的图像/空间方向为准，赛前需统一。 用于估计球门宽度、射门角度边界，以及守门时的左侧防守边界。
right_post 从机器人当前视角定义的右侧门柱坐标。 与 goal_center 同坐标系，当前固定使用 dummy。 用于估计球门宽度、射门角度边界，以及守门时的右侧防守边界。

五、点球进攻流程

1. 发布点球模式与射门参数 主控发布 /soccer/game_mode_cmd: PENALTY_ATTACK，同时携带 goal_target 和 nav_ball_distance_m。goal_target 使用归一化球门横向坐标，右门柱为 -1，左门柱为 1，左侧为正、右侧为负。
2. 导航计算定点导航点 点球点位置固定，导航不需要先找球。导航根据固定点球点、目标进球点和 nav_ball_distance_m，沿“目标进球点 → 足球”的延长线计算机器人应到达的定点导航点。
3. 立即执行定点导航 导航在收到 PENALTY_ATTACK 后立即开始导航到该点，并将 navigating_to_point=true 写入 /soccer/nav_status。这一阶段主控不发布行走速度，只等待导航状态。
4. 到点后打开视觉跟踪 导航到达定点导航点后广播 target_reached=true。主控收到后发布 /soccer/vision_track_cmd: START_BALL_TRACK，导航开始图像检测和球、球门坐标换算，并通过 /soccer/perception 广播球坐标和球门坐标。
5. 主控视觉微调 主控进入 ALIGN，根据 dummy/本体坐标系下的球位置做小步对位。此时导航只负责视觉坐标输出，不再负责运动控制。
6. 关闭视觉跟踪并射门 ALIGN 连续 N 帧满足距离、横向和朝向阈值后，主控发布 /soccer/vision_track_cmd: STOP_BALL_TRACK，导航停止图像检测。随后主控通过 deploy_cpp 的 /whole_body/action_ctrl action 发送 ExecutionUnit 射门请求。

六、守门流程

1. 模式切换 主控发布 /soccer/game_mode_cmd: GOALKEEPER，导航持续广播球坐标，并持有预设守门中心点；主控进入 TRACK_BALL。
2. 球轨迹估计 主控连续读取 /soccer/perception.ball，用多帧球坐标估计速度向量、轨迹和到达球门线的时间。
3. 拦截可达性判断 主控根据自己计算的拦截点判断是否可达；如果可达则横移到拦截位姿，如果不可达则选择覆盖近门柱或中心防守位姿。
4. 挡球动作触发 当主控计算的预计到达时间小于动作准备时间且轨迹置信度达标，主控通过 /whole_body/action_ctrl 触发对应的 BLOCK_LEFT/RIGHT/CENTER 全身动作；若守门动作尚未接入 deploy_cpp，则保持站位或空动作保护。
5. 防误判保护 球速度过低、轨迹方向远离球门、连续帧不一致时，只移动站位，不触发大动作。
6. 回中与再跟踪 完成挡球后回到守门中心点。守门回中仍使用导航的定点导航能力和 navigating_to_point/target_reached 状态，但不复用点球阶段的 /soccer/vision_track_cmd；具体回中命令可在守门协议落地时单独定义。

七、关键阈值与协作约定

时间同步

所有导航广播消息必须带 header.stamp。主控丢弃超过 200 ms 的 /soccer/perception 数据；守门轨迹建议使用最近 5-10 帧估计。

坐标系

视觉 SDK 只返回像素检测给导航。导航输出的每个 PointStamped.header.frame_id 必须明确，当前默认并固定使用 dummy。

点球对位阈值

建议初始值：横向误差 < 0.04 m，前后误差 < 0.06 m，朝向误差 < 0.08 rad，连续 5 帧满足才允许射门。

守门触发阈值

轨迹置信度 > 0.65，预计到达时间大于动作最小准备时间；若球速方向不指向球门线，保持站位观察。

异常仲裁

定点导航超时、target_reached 未到达、视觉跟踪后 image_has_ball=false 或坐标置信度低于阈值时，主控进入 HOLD 或 ERROR，禁止直接触发踢球。

日志与调参

三方统一记录时间戳、模式、状态、置信度和误差。比赛前用 rosbag2 回放检查接口稳定性。

八、状态机建议

模式 状态序列 进入条件 退出条件
PENALTY_ATTACK NAVIGATE_TO_POINT → START_BALL_TRACK → ALIGN → STOP_BALL_TRACK → READY_KICK → KICK → FINISH 主控收到点球进攻命令，导航和感知状态正常。 射门完成、超时、急停、导航到点失败或感知故障。
GOALKEEPER HOLD_CENTER → TRACK_BALL → INTERCEPT → BLOCK → RETURN_CENTER → RECOVER 主控收到守门命令，守门中心点和球门线坐标已标定。 挡球完成、回中完成、超时、急停或主控轨迹估计不可用。
CALIBRATION CHECK_CAMERA → CHECK_TF → CHECK_GOAL → READY 赛前调试或换场地后手动触发。 相机内参、外参、球门点和机器人初始位姿确认。
ERROR STOP_MOTION → REPORT → WAIT_RESET 急停、数据过期、动作失败、置信度持续过低。 主控收到 reset_state=true 且模块健康恢复。
